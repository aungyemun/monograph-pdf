Monograph PDF 0.5.1, released 2026-11-02. A maintenance release of the offline PDF editor for Windows 10/11 (64-bit) that corrects problems found after 0.5.0 was published: Check for Updates could fail with "Secure connection could not be verified", Ctrl+Tab did not switch document tabs, Save As onto a PDF open in another tab failed — or, for an unchanged document, overwrote that tab's file — and re-editing a filled-in PDF form showed old and new text on top of each other, did not save a cleared field, could not be undone, and kept the source program's font for pasted text.

## Defects corrected

- **Check for Updates on a correctly connected PC reported "Secure connection could not be verified".** GitHub's certificate chains to the Sectigo Public Server Authentication Root E46. 0.5.0 checked it with OpenSSL and a snapshot of the Windows certificate stores; where Windows had not yet installed that root, the check failed. 0.5.1 verifies certificates and host names with the Windows certificate chain engine, the verifier Windows itself uses. Verification is never switched off; the signed update information and the installer checksum are checked as before. **Note for 0.5.0 users:** if Check for Updates fails on 0.5.0, download 0.5.1 from this page.
- **Ctrl+Tab and Ctrl+Shift+Tab did nothing.** They select the next and previous document tab again, also while a text box or form field is being edited.
- **Save As or Save a Copy onto a PDF that is open in another tab.** Monograph PDF now says that the file is open in another tab and asks whether to close that tab and replace the file (naming unsaved changes in that tab, which would be lost) or cancel. Nothing is written before the choice. 0.5.0 showed a confusing error, or, for an unchanged document, replaced the other tab's file underneath it.
- **A failed Save As of an unchanged document no longer damages the destination.** A copy that failed part-way (for example on a full disk) left the existing file truncated; it now stays intact and no partial file is left.
- **Save errors name the cause**: read-only file, file in use by another program, folder permissions, missing folder or full disk.
- **Re-editing a filled-in PDF form no longer shows old and new text on top of each other.** Until the document was saved, the old value of a changed field stayed visible under the new one. Only the current value is shown now.
- **Clearing a field is saved.** Emptying a field that already had a saved value did not remove it; after Save the old text came back.
- **Checkboxes and radio buttons show their new state with the form's own mark** instead of the old state with a substitute symbol over it.
- **Form-field entries can be undone.** Typed entries, checkbox and radio clicks and Clear Field are on Edit ▸ Undo / Redo, one step per entry.
- **Text pasted into a form field takes the field's font and size.** Text copied from a web page, chat or word processor kept that program's font and size (for example "Segoe UI" 6.9 pt), and Japanese in such text was drawn in a gothic face that looked bold beside the form's Mincho text. Pasted text now looks like typed text; only bold, italic and real colours are kept.
- **A single click with the Line or Arrow tool no longer adds an invisible line** that was saved into the PDF and printed as a small dot (also in 0.5.0). Drag to draw a line.
- **User Guide:** how to fill a form field is described as it works (first click selects; a second click, double-click, Enter or Space starts typing).

## Compatibility

- Windows 10/11, 64-bit. Setup upgrades 0.5.0 and earlier installations in place and keeps settings and documents.
- New bundled component: truststore 0.10.5 (MIT), which connects Monograph PDF to the Windows certificate verification.
- Linux 0.1.0 and macOS 0.1.0 are unchanged.

## Verification for this release

- Automated tests in the release build (Windows 11, commit `d5f5c43`): 2160 passed, 0 failed, 43 skipped.
- Windows, Linux and macOS CI on the same code: passed.
- Save As integrity matrix with SHA-256 hashes of every file before and after (new file, existing file, file open in another tab with and without unsaved changes, own path, read-only, locked by another program, Unicode names, password-protected PDF, disk full): all cases keep every file intact.
- The update-check failure was reproduced with the Windows trust state before the Sectigo E46 root was installed, and the Windows certificate chain engine was shown to verify GitHub in that state.
- Installer test (`scripts/test_installer.ps1`, release candidate built from the same code before the release-date commit): 264 passed, 0 failed, 1 skipped — installation for the current user, registrations and shortcuts, the installer's self-check, start-up, uninstallation (also while the program runs and with a file in use), reinstallation, upgrade clean-up and the PDF Editor 0.1.5 migration; Windows 11 (English).
- Upgrades from the published 0.4.0 and 0.5.0 Setups into a folder with non-Latin characters in its name: 62 passed, 0 failed (settings and recent files kept byte for byte, no leftover program files, file registrations and shortcuts updated, the default PDF app unchanged).
- Not repeated for 0.5.1: installation for all users (per machine).

## Known limitations

- Windows 10/11 64-bit only; the installer and program are not code-signed.
- If a TLS-inspecting proxy or antivirus re-signs HTTPS traffic with a certificate Windows does not trust, Check for Updates reports that the connection could not be verified (by design).
- Other limitations of 0.5.0 remain (see the 0.5.0 release notes).
