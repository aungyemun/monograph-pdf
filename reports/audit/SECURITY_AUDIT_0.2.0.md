# Monograph PDF 0.2.0 — Security and Privacy Audit (release candidate)

Status: **0.2.0 is Unreleased.** This audit was run against the repository at the commit named in the release record. Results below are factual; items that could not be performed are marked as such.

Result: **no BLOCKER and no unresolved HIGH finding.** The MEDIUM finding (Pillow advisories) is fixed by the upgrade to Pillow 12.3.0. One LOW finding is known and open (finding 13).

## Method

Source review of every place that starts a program, writes or deletes files, reads user-chosen files or environment variables; static review of the Inno Setup script and its cleanup paths; `pip-audit` (OSV database) against the pinned `requirements.txt`; a repository secrets scan; inspection of the built `dist\MonographPDF\` folder; a runtime check of the built `MonographPDF.exe` with a PDF open (no TCP or UDP endpoints in the process or its children after 25 s); the offline self-check (`--smoke-test`) and the test suite.

## Findings

| # | Severity | Area | Finding | Status |
| :-- | :-- | :-- | :-- | :-- |
| 1 | MEDIUM | Dependencies | Pillow 11.1.0 (the version pinned when this audit started) had 17 known advisories fixed in Pillow 12.1.1 – 12.3.0 (PSD and JPEG 2000 decoder memory errors, decompression bombs, font and PDF-parser denial of service, native heap writes through public API misuse). Pillow reads a user-supplied file in two places (placing a picture, `export_image_box`, and saving it, `bake_edits`); every other use decodes PNG data produced by the application itself. Pillow is now pinned to 12.3.0. | Mitigated: both now decode only PNG, JPEG, BMP, GIF, TIFF and WEBP (`SAFE_IMAGE_FORMATS`), which removes the PSD and JPEG 2000 paths. **Fixed:** Pillow upgraded to 12.3.0; the full test suite, the packaged smoke test and the release checks were re-run. |
| 2 | LOW | External process | The printer name was placed inside a quoted `rundll32 printui.dll,PrintUIEntry /n "…"` argument; a printer name containing a quote could add arguments. Printer names are created by the local administrator. | Fixed: such a printer is not passed to rundll32. |
| 3 | LOW | Dependencies | fontTools 4.54.1: CVE-2025-66034 affects the `fontTools.varLib` command-line script (`.designspace` files). The application never runs that script. | Not reachable; fixed in fontTools 4.60.2 (needs a pdf2docx compatibility check). |
| 4 | INFO | Dependencies | pytest 8.3.4 advisory PYSEC-2026-1845 (UNIX `/tmp` directory handling). Development and test only; not shipped. | None needed. |
| 5 | INFO | Dependencies | OSV covers Python packages only. Native libraries inside the wheels (Qt, MuPDF, OpenCV) are not separately scanned by this tool. | Recorded. |
| 6 | INFO | Installer | Setup requests administrator rights by default and offers a per-user install (`PrivilegesRequiredOverridesAllowed=dialog`). Nothing is written to Program Files at run time; user data lives under `%APPDATA%` and `%LOCALAPPDATA%`. | As designed. |
| 7 | INFO | Installer cleanup | Internal compatibility: upgrade of an earlier internal build's folder (no file list) removes an allowlist of application names (`_internal`, `engines`, `models`, `docs`, `licenses`, `logs`, `runtime`, `packages`, the two executables, the notices). Every path is checked to stay inside an accepted install folder, reparse points are skipped, and the folder itself is removed only when empty. Unknown files are kept. | Verified by the installer test (user file kept). |
| 8 | INFO | Uninstall | Internal compatibility: data folders of an earlier internal build are removed only for a user whose first-start migration record exists and only when no program of that build remains. Folders that are links, that contain the install folder, or that are not named like product data folders are never removed. Temp cleanup matches only `monographpdf*`, `monograph-pdf-theme`, `pdfeditor*`, `pdf-editor-theme` (earlier internal names) directories that are not reparse points. | Verified by the installer test. |
| 9 | INFO | Migration | First-start migration copies preferences, existing recent files and version-1 recovery sessions; it never deletes, never follows links and is skipped when `MONOGRAPH_PDF_USER_DATA_DIR` or `MONOGRAPH_PDF_NO_LEGACY_MIGRATION=1` is set. Recovery sessions can contain unsaved text; they stay in the same user profile. Password-protected PDFs never get a recovery copy. | As designed. |
| 10 | INFO | Privacy | No code path imports a network library other than the socket guard used by the self-check; the OCR child process has proxy variables removed. The built application showed no TCP/UDP endpoints during the runtime check. This is not a packet capture. | Claim consistent with the observed behaviour. |
| 11 | INFO | Updates | The application has no update check and downloads nothing. | None. |
| 12 | INFO | Signing | The build is not code-signed; `SHA256SUMS.txt` is the integrity reference. | Documented in the README. |
| 13 | LOW | Usability | **Show in folder** starts `explorer.exe` without catching `OSError`; if Explorer cannot start, no message is shown. No crash or data loss. | Known; not changed in this release candidate. |

## Checklist coverage

Dependencies and bundled components (1, 2, 3): pip-audit result above, `THIRD_PARTY_NOTICES.md` checked by the release-content validation. Secrets (4): no tokens, keys or credentials in the tree; only test passwords in the release smoke script. Repository and release contents (5, 6): validated by the source-archive and release-content checks. Installer privilege and Program Files behaviour (7, 8): code review; **the elevated Program Files upgrade path was verified by code review and by the non-elevated installer matrix; the privileged Program Files scenario is reported as skipped when the test host cannot run it elevated.** User data, temp, recovery (9, 10, 11): findings 8–9. Paths, traversal, overwrite, reparse points (12–15): relative-path validation and reparse-point checks in Setup, link checks in the migration, `windows_tool()` full paths. PDF parser and renderer, malformed files, encryption (16–18): MuPDF is the only PDF parser; passwords are held in memory only and never logged, stored or written to a recovery copy (checked by source search). OCR and external processes (19–21): argument lists without a shell, fixed executables inside the installation, `PATH` and the current folder not searched for LibreOffice. DLL loading (22): no `LoadLibrary` calls; the one `ctypes` use is the Windows known-folder lookup; PowerShell and rundll32 are started by full system path. Environment variables (23): `MONOGRAPH_PDF_*` before deprecated `PDFEDITOR_*`; the file names passed to PowerShell travel in environment variables, never inside script text. Network, privacy, updates (27–29): findings 10–11. Artifact integrity (30): `SHA256SUMS.txt` regenerated from the final build.
